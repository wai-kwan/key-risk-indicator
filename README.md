# KRI Skill: Key Risk Indicator Generator

**License**: Apache-2.0\
**Specification**: agentskills.io framework compatible\
**Author**: wai-kwan (https://github.com/wai-kwan)

Generates quantifiable **Key Risk Indicators (KRIs)** with Green / Amber / Red trigger thresholds for enterprise risks, and saves them to a spreadsheet friendly `kri_register.csv`. It is the companion of the [erm skill](https://github.com/wai-kwan/enterprise-risk-management): erm builds the risk register, this skill builds the monitoring framework for it. It also reads registers from the [risk-discovery skill](https://github.com/wai-kwan/risk-discovery), which discovers risks through a facilitated workshop or interview.

- Prioritises **leading** indicators (early warning) as far as possible, with **lagging** ones (after the fact) only once good leading ones are exhausted
- **Up to 10 KRIs per risk** per run, sized by risk criticality (3 to 10 by default) unless you ask for a number
- Every KRI has a measurement method, frequency, and a **Low (Green) / Medium (Amber) / High (Red)** threshold
- Works with a full risk register, a partial or non-standard one, in any file name, or a single risk typed into the prompt, and can call the [erm skill](https://github.com/wai-kwan/enterprise-risk-management)'s Completion Mode to fill in missing risk parameters
- Re-runnable: ask for more KRIs to choose from, or replace the ones you do not like

The KRIs generated by this skill are meant to give you ideas of appropriate KRIs to monitor your risks. The KRIs and their trigger thresholds can be fine-tuned to fit the specific context of your risks and risk environment.

## Installation
Place the `kri` skill folder into your active workspace or your global agent skills directory. As the [agentskills.io specification](https://agentskills.io/specification) requires, `SKILL.md` must sit at the top of the folder and the folder name (`kri`) must match the skill `name`.

### Workspace Setup (Local Repo)
To activate the skill automatically inside a project workspace, copy the folder like so:

```
your-project-repository/
└── .github/
    └── skills/
        └── kri/
            ├── SKILL.md
            └── references/
                └── example_kri_register.csv
```

Other agents load skills from their own folders (for example `.claude/skills/kri/` for Claude Code), so use the location your agent expects.

### Direct CLI Installation (When using tools like agentskills CLI)
```bash
npx skills add wai-kwan/key-risk-indicator
```

### Claude (claude.ai)
Download the packaged `kri.skill` file from this repository and upload it under Settings, Capabilities, Skills, or use the Save skill button on the file card.

### Recommended companions: the erm and risk-discovery skills
The kri skill works on its own, but when your risk register is missing or incomplete it invokes the [erm skill](https://github.com/wai-kwan/enterprise-risk-management)'s Completion Mode (erm 1.2.0 or later) to complete the missing risk parameters. The [risk-discovery skill](https://github.com/wai-kwan/risk-discovery) helps you discover the risks in the first place, through a facilitated workshop or interview. Install them alongside it:

```bash
npx skills add wai-kwan/enterprise-risk-management
npx skills add wai-kwan/risk-discovery
```

## Quick start
1. (Optional) Build your risk register first:
   - run the [erm skill](https://github.com/wai-kwan/enterprise-risk-management) to identify and rate risks into `risk_register.csv`, or
   - run the [risk-discovery skill](https://github.com/wai-kwan/risk-discovery) to discover your team's own top risks in a facilitated session.

   If you skip this and your register is missing or incomplete, the kri skill will call erm for you when it is installed. You can also use your own register file in any name or layout.
2. After the kri skill is installed, you can ask for KRIs in plain language, for example:
   - `Generate KRIs for my risk register.` (reads `risk_register.csv`)
   - `Create KRIs for Q3_supply_risks.xlsx.` (any file name)
   - `Use the kri skill to give me KRIs for R1 and R3 only.`
   - `/kri give 5 KRIs for the CRITICAL risks.`
   - `Generate KRIs for this risk: loss of our sole cloud provider causing a multi day outage.`
3. Open `kri_register.csv` in Excel, Google Sheets or Numbers.
4. The skill generates KRIs with three traffic-light style trigger thresholds:
   - **Low (Green)**: acceptable, routine monitoring only
   - **Medium (Amber)**: drifting towards the limit, investigate and prepare
   - **High (Red)**: breached, high alert, act now

### Invoking the skill
The skill activates automatically when you ask for KRIs or early warning indicators, so a plain request is enough. In agents that support calling a skill by name (for example Claude Code), you can also force it with the slash command `/kri`. Whatever follows `/kri` is read as an ordinary request, not as command options, so write it as a sentence.

| Slash command | Plain language equivalent |
|---|---|
| `/kri` generate KRIs for my risk register | "Generate KRIs for my risk register." |
| `/kri` for R1 and R3 only | "Generate KRIs for R1 and R3 only." |
| `/kri` give me 5 more for R2 | "Give me 5 more KRIs for R2." |
| `/kri` for this risk: loss of our sole cloud provider | "Generate KRIs for this risk: loss of our sole cloud provider." |

Slash invocation is optional and varies by agent, so if `/kri` is not recognised in yours, use the plain language form.

## Inputs
| Input | What you provide | How the skill behaves |
|---|---|---|
| Full register (preferred) | The 14 column register from erm (default name `risk_register.csv`) | Uses the Causes, Effects, controls and criticality to build precise KRIs |
| risk-discovery register | The register saved by a risk-discovery session (for example `2026-11-02_company-operations_risk_register.csv`) | Read like any other register. A rank only session has no ratings, so erm proposes them first when it is installed |
| Partial or non-standard register | A file or table with only some columns or cells filled, or in a different layout, with at minimum a risk description per risk | Invokes erm's Completion Mode if available to complete the missing parameters, otherwise infers missing Causes and Effects (marked `Inferred:`), assigns missing Risk IDs, derives criticality from likelihood and impact if available, otherwise `Not rated` |
| Single risk in the prompt | One or more risks described in a sentence, no file | Treats the sentence as the risk, invokes erm if available to assess it, otherwise infers Causes and Effects, assigns Risk ID `R1` (or next unused) |

By default the skill looks for `risk_register.csv` in the workspace directory. To use a different file, name it in your prompt or give its path or upload. Your original file is never renamed, moved or changed. If there is nothing at all to work from, it asks you for a risk rather than inventing one.

### Non-standard registers
If your file does not follow the erm layout (different column names, a different order, missing columns, or just a plain list of risks), the skill does not reject it. It extracts the in-scope risks and whatever parameters it can recognise by meaning (for example "Root cause" is read as Causes), ignores the columns it cannot use, and carries on.

### When the register is missing or incomplete: using the erm skill
If any risk lacks Causes, Effects or a rating, has only one Cause or one Effect, or you only describe a risk in the prompt, the skill first checks whether the [erm skill](https://github.com/wai-kwan/enterprise-risk-management) is available in your workspace.

- **erm available:** the skill hands your risks to erm's **Completion Mode**, then generates the KRIs from the completed register.
  - **Your own values always win.** erm never rewords or removes what you wrote, and keeps your Risk IDs. It fills the empty fields (causes, effects, likelihood, impact, score, criticality and controls), and where you gave only one Cause or Effect it adds more after yours, aiming for 2 to 3 of each.
  - **erm's additions are kept**, so every Cause, including any erm added, gets at least one leading KRI. The closing message lists the risks erm completed or topped up, and erm's ratings and additions are proposals for you to review.
  - The completed register is saved as a **new file** named after yours with `_kri` added: `risk_register.csv` becomes `risk_register_kri.csv`, and `Q3_supply_risks.xlsx` becomes `Q3_supply_risks_kri.csv`. A risk typed into the prompt produces `risk_register_kri.csv`.
  - Your original file is **never renamed, overwritten or edited**.
  - On later runs the `_kri` file is reused, so erm is not run again for risks it has already completed.
- **Older erm (before 1.2.0, without Completion Mode):** the skill still uses it through its standard workflow, fills only the missing fields, and suggests updating erm.
- **erm not available:** the skill carries on without it. It infers the missing Causes and Effects (2 to 3 per risk, keeping any you gave, marked `Inferred:`) and uses `Not rated` where there is no rating. No new register file is written. It will not try to install erm for you, but it will tell you where to get it.

A register that is missing only controls or category is treated as complete enough, so erm is not invoked.

## Risk register format used to generate KRIs
The **preferred input is the full `risk_register.csv` generated by the [erm skill](https://github.com/wai-kwan/enterprise-risk-management)**, because its Causes, Effects, ratings and controls let the kri skill design the most precise KRIs. However, only one column is truly required: the **risk description**, which identifies each risk and determines which risks are in scope. Every other column can be missing, and the kri skill will complete it by invoking the erm skill, or infer it if erm is not available.

| Column | Used for | Required? | If missing |
|---|---|---|---|
| **Description** (risk description) | Identifying the risk and deciding what is in scope | **Yes** (a Risk Title alone is accepted and used as the description) | Cannot proceed for that risk |
| Risk ID | Referring to risks and numbering KRIs (`R1.K1`) | No | Assigned R1, R2, ... (by erm in score order when it is used) |
| Risk Title | Labelling the risk and selecting by keyword | No | Written from the description |
| Category | Selecting by Strategic, Operational or Financial | No | Assigned by erm, else left blank |
| Causes (Drivers) | Designing the leading KRIs, one or more per cause | No | Generated by erm (2 to 3, or topped up if you gave only one), else inferred and marked `Inferred:` |
| Effects (Consequences) | Designing lagging KRIs and loss reducing control checks | No | Generated by erm (2 to 3, or topped up if you gave only one), else inferred and marked `Inferred:` |
| Likelihood Scale (1-5) and Impact Scale (1-5) | Working out the risk score and criticality | No | Generated by erm, else criticality is `Not rated` |
| Risk Score | Mapping to criticality if the scales are absent | No | Calculated, or generated by erm |
| Risk Criticality | Setting the default number of KRIs and the tightness of thresholds | No | Calculated from the score, generated by erm, else `Not rated` (treated as MODERATE) |
| Preventive Controls and Reductive Controls | Designing KRIs that monitor the health of controls | No | Generated by erm, else ignored |
| Likelihood and Impact (text labels) | Not used | No | Not needed |

### Preferred format: the erm risk register
```csv
Risk ID,Category,Risk Title,Description,Causes (Drivers),Effects (Consequences),Likelihood Scale (1-5),Likelihood,Impact Scale (1-5),Impact,Risk Score,Risk Criticality,Preventive Controls,Reductive Controls
R1,Strategic,Inability to capitalise on the advancement of AI,Unable to harness the advancement of AI to maintain the lead position of the company.,"* Lack of AI talent.
* Pace of AI advancement too rapid to keep abreast.","* Loss of business to competitors.
* Higher operating costs than AI enabled competitors.",4,Likely,5,Severe,20,CRITICAL,"* Increase headcount budget for AI talents.
* Create an AI task force to oversee the deployment of AI in the company.","* Incorporate AI capabilities in the company's star products.
* Use AI to automate high volume internal processes."
R3,Financial,Unfavourable FX Exchange Volatility,Unfavourable FX exchange affecting the global revenue.,"* Macroeconomic shift in fiscal policy.
* Interest rate changes in major markets.","* Revenue losses.
* Unpredictable earnings for budgeting.",2,Unlikely,4,High,8,MODERATE,"* Monitor treasury forex indices weekly.
* Set a treasury policy with limits on currency exposure.","* Secure fixed forward-hedging capital contracts.
* Budget with conservative exchange rate assumptions."
```

### Minimum acceptable input
A file with nothing but risk descriptions works. Any column names are fine for the description column.
```csv
Description
Loss of our sole supplier disrupting production for several weeks.
Key engineers leaving to join a competitor during the product launch.
```
The skill reads each line as a risk, then fills in the IDs, titles, causes, effects and ratings (through the erm skill if available, otherwise by inference).

## Choosing which risks
If you do not say, KRIs are generated for **all risks** in the input. If your selection matches nothing (for example an unknown Risk ID), the skill tells you so and stops, so check the ID or keyword and try again. You can narrow it by:
- Risk ID: `R2`, `R1 and R5`, `R1 to R5`
- Title or keyword: `the cyber risk`
- Category: `Operational risks only`
- Criticality: `CRITICAL and HIGH only`
- Rank: `top 3 risks`

## Number of KRIs
| You say | You get |
|---|---|
| Nothing (default) | CRITICAL 7 to 10, HIGH 5 to 8, MODERATE or Not rated 4 to 6, LOW 3 to 4 KRIs per risk |
| `5 KRIs for R2` | Exactly 5 for R2 |
| `6 each` | 6 per selected risk |
| `8 for R1 and 4 for R3` | Per risk numbers as stated |
| Fewer than 3 | Exactly the number you ask for (there is no minimum) |
| More than 10 | Capped at 10 for that run, then use the add option below for more |

## Re-running
Each run reads the existing `kri_register.csv` first, so nothing is lost by accident.

| You say | Mode | What happens |
|---|---|---|
| `Give me 5 more KRIs for R2`, `other options`, `additional KRIs` | **Add** (default) | Existing rows kept. New, genuinely different KRIs are appended with the next IDs (for example `R2.K7`). Existing IDs never change. |
| `Redo R1`, `regenerate`, `these are not good` | **Replace** | The old file is saved as `kri_register_previous.csv`, then only the selected risks are regenerated from `K1`. Other risks are untouched. |
| `Too generic`, `thresholds too loose`, `our attrition baseline is 12%` | Feedback | Your feedback and any real baselines are applied in Add or Replace mode, whichever fits. |

Add mode is meant for building a **pool of candidates**: a risk can end up with more than 10 rows across runs. Delete the rows you do not want and keep the best.

## Output: `kri_register.csv`
One row per KRI, 12 columns:

| Column | Meaning |
|---|---|
| Risk ID, Risk Title, Risk Criticality | Carried over from the register (or assigned or inferred) |
| KRI ID | `<Risk ID>.K<n>`, for example `R1.K1` |
| KRI Name | Short title |
| KRI Description and Measurement | What is tracked, why it signals the risk, and how it is measured (formula or data source, unit) |
| Measurement Frequency | Daily, Weekly, Monthly, Quarterly or Annually |
| Indicator Type | `Leading` or `Lagging` |
| Linked Cause or Effect | The Cause (leading) or Effect (lagging) it tracks, traced back to the erm analysis; `Inferred:` if it was inferred by this skill without erm |
| Low (Green) Threshold | Acceptable, routine monitoring only |
| Medium (Amber) Threshold | Drifting towards the limit, investigate and prepare |
| High (Red) Threshold | Breached, high alert, act now |

Threshold bands are numeric, mutually exclusive and cover every possible value, with explicit operators (`<=`, `>`, and so on) so the direction of each metric is unambiguous.

Example row:
```csv
R1,Inability to capitalise on the advancement of AI,CRITICAL,R1.K1,AI engineering vacancy rate,"Tracks unfilled AI roles that slow AI delivery. Measured as open AI roles divided by approved AI headcount.",Monthly,Leading,Lack of AI talent,<= 10%,> 10% and <= 20%,> 20%
```
A complete worked example for the erm sample register is in `references/example_kri_register.csv`.

## How leading and lagging KRIs are chosen
- **Leading** KRIs measure conditions that precede the event (a Cause or the health of a Preventive Control), so there is still time to act.
- **Lagging** KRIs measure outcomes after the event has started (an Effect or a failed control). They are still acceptable, but only after the good leading KRIs have been exhausted.
- Every Cause gets at least one leading KRI. There is no fixed lagging quota: the skill generates as many good leading KRIs as it can first, and fills the remainder with meaningful lagging ones.

## Important notes
- **Thresholds are starting points.** They are based on general practice and the risk context. Calibrate them against your organisation's risk appetite, historical data and real baselines, or tell the skill your numbers and re-run.
- **Inferred and proposed content.** When you supply only a risk description, the Causes and Effects are inferred or proposed by erm, and erm's ratings are proposals too. Review them, since the KRIs are only as good as the underlying causes.
- The skill only generates KRIs. It does not collect data or monitor values over time.

## Relationship to the erm and risk-discovery skills
The [erm skill](https://github.com/wai-kwan/enterprise-risk-management) creates `risk_register.csv` (risk identification, causes and effects, rating, criticality and controls), and the [risk-discovery skill](https://github.com/wai-kwan/risk-discovery) creates a register from a facilitated session. This skill reads either file (or any register file you name) to create `kri_register.csv`. All three use the same 14 column register format and CSV conventions: no space after delimiter commas, double quoted cells where needed, and no hyphens starting a cell.

A typical flow: discover risks with risk-discovery, complete and rate them with erm, then create KRIs with kri. Using erm or risk-discovery first is recommended but optional: if the register is missing or incomplete, this skill invokes erm's Completion Mode itself when it is available, saving the completed register as `<your file name>_kri.csv` and leaving your original untouched.
